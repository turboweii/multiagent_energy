# 先补偿用户、再分净收益的算力合同改签机制

本文说明当前 `amendment_market.py` 的机制和评价口径。研究目的保持为：在输电拥塞和碳约束下，利用分时、分区算力报价，引导独立用户自愿迁移或延迟任务，在完成相同任务量、满足相同截止期的条件下降低系统成本，并让参与者获得可接受的收益。

这一版以**已经接受的旧制度合同**为起点。平台、三个用户以及电力系统侧的合并采购账户，共同分配改签带来的经济增量。平台继续有自己的 PPO，三个用户分别有独立 PPO；电网通过 DCOPF 按规则出清。

## 一、先形成旧合同，再接受有条件的改签提案

一天内的顺序如下：

1. 固定当天的任务、私有偏好、背景负荷、可再生出力、发电与输电参数，并在任何报价之前确定共同碳上限。
2. 用训练和验证阶段已经选定、随后冻结的旧平台策略和旧用户策略，形成当天所有任务的旧预约合同。记录各任务的执行方案、账单、用户不便损失，以及整个平台的旧利润。
3. 新平台发布一次额外折扣菜单。每个用户按任务顺序选择保留旧合同，或提出一个改签方案。
4. 对改签提案，先检查计算容量、带宽、报价额度、供电和共同碳上限，再按本节后文的结算制度检查公开经济条件。用户还可以根据自己的账单与不便损失拒绝改签。
5. 通过全部条件的提案才成为新合同；未通过时，履行原来已经接受的旧合同。所有任务只按最终合同执行一次。

这里的旧方案在第二阶段开始前已经形成确定预约。平台收入底线因此是一个可以执行的合同收益，而非测试日遍历全部旧报价后找到的最好收益。旧策略的选择只使用训练和验证场景。

新合同的物理和经济条件在成交前检查。已成交改签不会在日终因为平台利润不够而撤销。后续任务提出改签时，先前已经成交的改签也保持不变。

## 二、旧收入底线和用户意愿分别怎样定义

用上标 `old` 表示当天已经接受的旧合同组合：

\[
\Pi^{old}=Q^{old}-B^{old}-K^{old}-F.
\]

其中，`Q` 是算力用户账单之和，`B` 是整个平台全部数据中心的节点电费，`K` 是可变计算与迁移运行成本，`F` 是当天固定算力容量成本。固定成本在同一天的方案比较中相同。

任务 `j` 的旧合同已有账单 \(q_j^{old}\) 和绝对不便损失 \(D_j^{old}\)。改签后账单为 \(q_j^{new}\)，不便损失为 \(D_j^{new}\)，因此：

\[
R_j=q_j^{old}-q_j^{new},\qquad
\Delta D_j=D_j^{new}-D_j^{old},\qquad
U_j=R_j-\Delta D_j.
\]

`R_j` 是额外补偿，`U_j` 是用户相对已签旧合同的效用增量。用户接受改签需要 \(U_j\ge0\)。如果改签消除了原有延期或迁移，\(\Delta D_j\) 可以为负，零折扣也可能使用户受益。保留旧合同的增量账单、不便损失和效用均为零；旧合同本来具有的不便损失仍保留在绝对成本中。

用户的绝对不便损失继续由其私有时间敏感度和迁移敏感度计算：

\[
D_j=W_j\beta_i\tau_j+W_j\kappa_i\mathbf1\{\text{相对原始地点发生迁移}\}.
\]

新报价按旧账单的平均 GPU 小时单价给予额外折扣。令 \(\bar v_j^{old}=q_j^{old}/W_j\)，新方案在时间 `t`、地区 `n` 的工作量为 \(x_{jnt}\)，公开折扣为 \(d_{nb(t)}\)，则：

\[
R_j=\bar v_j^{old}\sum_{n,t}x_{jnt}d_{nb(t)},\qquad
q_j^{new}=q_j^{old}-R_j.
\]

只有相对旧合同发生实际物理变化的方案才获得额外折扣。相同执行方案重复预约不能领取新补偿。所有选项仍完成同一工作量，并遵守原释放时间和硬截止期。

## 三、逐任务核实资源节约与平台电费节约

以下 `before` 是处理当前任务前已经预约的完整计划，`after` 只替换当前任务的执行方案。两者均保留其他已成交合同和后续任务的旧预约。

| 符号 | 含义与口径 |
| --- | --- |
| \(C\) | 全电网发电资源成本，不含碳支付和电费转移 |
| \(K\) | 平台可变计算和迁移运行成本 |
| \(B\) | 全部数据中心按该完整计划重新出清后的节点电费 |
| \(G_j\) | 当前改签带来的资源成本节约 |
| \(a_j\) | 当前改签带来的平台电费及可变运行成本节约，尚未扣额外补偿 |
| \(M_j\) | 支付用户额外补偿后剩余的可分配净收益 |
| \(p_j\) | 当前改签结算后的平台增量利润；这里的小写 `p` 表示利润增量 |
| \(T_j\) | 合并采购账户与平台之间的增量结算调整，正值为账户支付平台 |

\[
G_j=(C_{before}+K_{before})-(C_{after}+K_{after}),
\]
\[
a_j=(B_{before}+K_{before})-(B_{after}+K_{after}),
\]
\[
M_j=G_j-R_j.
\]

任务迁移会改变节点电价，也可能改变其他数据中心的电费。因此，\(a_j\) 使用**整个平台电费的变化**。\(G_j\) 同样来自完整电网重新出清后的成本差。采购计算不使用私有 \(D_j\)、\(\beta_i\) 或 \(\kappa_i\)。

`先补偿` 指从资源收益中先扣除用户补偿，再分配余额；它是事先公布的合同结算顺序。付款由最终接受的合同和约定结算公式确定。

## 四、三种结算制度

分成比例 \(\alpha\) 事先给定，当前设定为 `0.8`。三个制度使用相同的任务、旧合同、物理约束和报价菜单，差别在于预成交经济条件及结算方式。

| 制度 | 公开经济准入条件 | 平台增量利润 \(p_j\) | 系统侧账户增量 \(V_j\) |
| --- | --- | --- | --- |
| `direct`：直接报价、无额外转账 | \(a_j-R_j\ge0\) | \(a_j-R_j\) | \(G_j-a_j\) |
| `gross`：先分资源毛收益，再补偿用户 | \(\alpha G_j-R_j\ge0\)，且 \(M_j\ge0\) | \(\alpha G_j-R_j\) | \((1-\alpha)G_j\) |
| `net`：先补偿用户，再分净收益 | \(M_j\ge0\) | \(\alpha(G_j-R_j)\) | \((1-\alpha)(G_j-R_j)\) |

三种制度都还需要通过物理检查和用户自己的参与条件。实现对接近零的经济量使用 `1e-7` 元数值容差。

统一的结算表达式是：

\[
T_j=p_j-(a_j-R_j),\qquad V_j=G_j-R_j-p_j.
\]

`direct` 的 \(T_j=0\)。该制度按平台自己的增量利润判断是否成交，\(V_j\) 可以为负，这个值照实报告。`gross` 和 `net` 在其准入条件下保留非负系统侧账户增量。

对同样的 \(G_j,R_j\)，净收益分配使平台相对毛收益分配多保留 \((1-\alpha)R_j\)，采购账户相应少保留这一金额。这表示用户补偿的负担由平台和账户按比例共同承担。账面分配本身不改变资源成本，系统成本下降仍需要任务执行和发电安排产生实际变化。

以纯公式示例说明区别：若某提案有 \(G_j=100\) 元、\(R_j=90\) 元、\(a_j=120\) 元，且用户与物理条件都满足，那么：

- `net` 有 \(M_j=10\)，平台得 `8` 元，账户得 `2` 元，\(T_j=8-(120-90)=-22\) 元；提案可成交。
- `gross` 有 \(p_j=80-90=-10\) 元；提案在成交前被拒绝，原合同继续履行。
- `direct` 有 \(p_j=120-90=30\) 元、\(V_j=100-120=-20\) 元；平台愿意成交，但系统侧账户承受负增量。

该例仅解释公式。制度改变了用户补偿的边际成本和可成交方案集合，实际成本与利润变化由训练后的对比测量。

## 五、采购账户与完整增量恒等式

这里的采购方是**电力系统侧增量受益的合并结算账户**。在新增转账之前，\(G_j-a_j\) 表示发电、其他用电等系统侧主体合计的经济增量；\(T_j\) 调整该账户与平台之间的收益分配。

实施这种结算，需要约定按核实资源节约回收和结算收益的灵活性采购安排。合并经济增量不等于 ISO 天然拥有的可支配现金。净收益机制保护的主体是平台、三个算力用户和这一合并账户；它没有逐一保证每个发电企业、其他用电用户或结算接收方均不受损。`direct` 对照只保护平台和算力用户的参与条件，保留系统侧账户可能为负的增量。

令 \(\Delta D=\sum_j(D_j^{final}-D_j^{old})\)。各次成交的成本差和现金差逐笔累加后，有：

\[
\Delta\Pi=\Pi^{final}-\Pi^{old}=\sum_jp_j,
\]
\[
S_{old}=\sum_jG_j-\Delta D
=\Delta\Pi+\underbrace{\left(\sum_jR_j-\Delta D\right)}_{\text{用户增量效用}}
+\underbrace{\sum_jV_j}_{\text{合并采购账户增量}}.
\]

这些都是相对已签旧合同的增量。旧制度原有的发电、电费及其他支付分配仍作为起点，不能把系统侧旧账户清零后宣称全体主体获得了正收益。

平台固定成本在同日差值中抵消，收入底线仍按包含固定成本的实际利润计算。对 `net`，每笔成交有 \(M_j\ge0\)，从而 \(\sum_jp_j\ge0\)，保证 \(\Pi^{final}\ge\Pi^{old}\)。用户参与条件给出 \(\sum_jR_j-\Delta D\ge0\)，合并账户也保留非负增量，所以 \(S_{old}\ge0\)。这些结论来自合同与准入规则。

## 六、共同碳上限和价格传导

当前仿真同时保留发电侧外生碳价和全天排放上限。各制度使用相同的发电侧碳价，当前默认 `100 元/吨`；电力出清求解：

\[
\min\sum_{t,g}(c_g+\pi e_g)P_{gt}\Delta t,
\qquad
\sum_{t,g}e_gP_{gt}\Delta t\le\overline E.
\]

共同碳上限在任何旧报价或新改签之前确定：先用**原始原地原时任务**、当天相同电网和发电侧碳价，计算未施加硬碳上限的参考出清排放 \(E^0\)，再设：

\[
\overline E=E^0+10^{-7}\ \text{吨}.
\]

旧制度预约、`direct`、`gross`、`net` 和所有固定报价对照都使用这一个全天物理上限。上限不会按旧优化计划或新报价结果重新设定。

节点电价来自 OPF 的节点平衡对偶值；碳上限影子价格来自同一出清。外生碳价已经通过机组报价进入电价，平台不重复支付同一项碳费用。当前也不向平台利润奖励另加内部碳偏好，`eta=0`。

任务位置和时间变化会改变节点负荷、线路利用、发电结构、电价和碳约束的稀缺程度；它们又改变改签的 \(G_j\)、\(a_j\) 及可成交性。平台可观察公开电碳信号和物理预测，用户仍按自己的账单和私有不便损失选择合同。

共同上限只保证各方案都满足同一碳约束。旧方案若已经低于上限，新方案仍可能比旧方案排放更高。因此要单独报告 \(E^{old}-E^{final}\)，并区分全电网实际排放与分摊到数据中心的用电碳足迹。

## 七、平台与用户动作，以及四个 PPO 的分工

平台使用相同的 `Discrete(78)` 菜单：

- `0`：结束改签轮，履行全部旧合同。
- `1`：开放零额外折扣的改签轮。
- `2–77`：原固定菜单中 76 个非零分区、分时报价，加上开放改签标志。

报价形状与电碳信号相互独立，由平台 PPO 根据公共信息选择。菜单的公开预约额度均为完整物理容量。底层动作包含原 15 个价格与额度分量，再增加一个是否开放改签的标志。

每个用户仍有十个动作。动作 `0` 重新定义为自己的已签旧执行方案；其他物理不同的执行方案去重后排列，不足十项的部分作为不可选填充。用户返回原始地点和时间也可能构成一次真正改签，因为其旧合同可能已经迁移或延期。

用户状态给出相对旧合同的单位工作量账单差、不便损失差、延期差及公开可成交资格。公开资格与实际预成交检查使用同一组物理及经济条件，不包含用户私有参与判断。用户的奖励是实际接受合同后的 \(U_j/W_j\)，未成交提案的增量奖励为零。

平台奖励为当天实际额外现金利润 \(\Delta\Pi/1000\)。采购转账直接进入平台现金利润。三个用户分别优化自己的效用，平台优化自己的利润。首先固定相同的已适应改签规则的用户 PPO，比较各制度的平台 PPO；随后四主体交替训练的结果另外列出，以辨别用户策略变化的影响。

当前按单任务顺序预约，采购准入核实当前改签的增量。需要多个任务同时改变才能产生的互补收益，尚不属于这一单任务成交协议的可实现集合。

## 八、结果分别相对哪个基准

| 比较起点 | 含义 | 主要字段 |
| --- | --- | --- |
| 已接受旧合同 | 用户和平台实际可履行的外部方案，也是本轮改签的参与底线 | `outside_*`、`platform_gain_vs_outside_yuan`、`incremental_system_cost_saving_vs_outside_yuan` |
| 原始原地原时方案 | 同一批任务最初的执行方式，用于观察旧制度与改签叠加后的总变化 | `original_*`、`delta_*_vs_original` |
| 同碳上限的纯背景负荷成本 | 展示算力任务增加的成本规模 | `background_only_generation_cost_yuan`、`incremental_system_cost_yuan` |

系统运行成本为 \(C+K+D\)。电费、算力账单和采购转账分别影响各主体收益，不重复加入这一成本。完整成本额外包括同日固定算力容量成本。

改签主要节约是：

\[
S_{old}=(C^{old}+K^{old}+D^{old})-(C^{final}+K^{final}+D^{final}).
\]

相对原始方案的总节约还包含旧制度已实现的变化，两者分别列示。报告同时给出相对全系统旧成本的节约率，以及相对“扣除纯背景负荷后”的旧增量成本节约率，分母在名称中标明。

比较使用相同场景和相同旧预约。默认一个算法种子 `0`，训练场景 `0–63`，验证场景 `1000–1015`，最终测试场景 `50000–50031`。算法种子与仿真日场景编号是两个概念。

## 九、怎样判断 PPO 和机制各自的效果

平台旧利润底线、用户保留旧合同、共同碳约束、任务量和截止期，以及 `net` 的合并账户非负增量，均由合同与准入规则提供。报告这些约束的满足情况，用于确认方案的成交含义。PPO 的作用需要通过另外的效果比较衡量。

同一天的主要对照包括：

1. **旧合同原样履行。** 衡量第二阶段的全部增量。
2. **零额外折扣开放改签。** 衡量无需额外价格激励时，重新预约本身能带来多少变化。
3. **`direct` 的第二轮改签。** 它与另外两种制度同样多一次优化机会，保留旧平台利润底线，采用相同菜单和用户；用于识别分成与补偿顺序的作用。
4. **训练集选出的最强固定菜单。** 在相同冻结用户下遍历 78 个常数菜单，以训练日平均额外平台利润选择一个，之后固定用于测试。另外单列只从 `2–77` 中选出的最强额外折扣常数。
5. **平台 PPO。** 在同一冻结用户、同一报价集合上，根据公共场景信息选择报价，与免费改签和两个固定菜单基准逐日配对比较。
6. **联合训练的四 PPO。** 使用验证集选择整组策略，单独展示，因其用户权重可能已与主要比较不同。

评价包括：相同工作量下的额外系统与资源成本节约、平台额外现金利润、三个用户各自的效用增量、合并采购账户增量、补偿和正负转账、改签数量及全电网实际排放变化。平台在不同场景调整报价是否比强固定报价带来更好的实际收益，是学习效果的直接证据。

测试日逐日遍历菜单得到的最好值，如需计算，只作为明确标注的事后有限菜单参考，不能拿来充当可实施旧合同、测试日平台策略或模型选择依据。平台始终选择退出时，其改签增量就是零；仅有参与底线满足不能说明 PPO 学到了有效报价。
