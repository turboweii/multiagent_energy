# 多报价合同学习与压缩报价的四主体 PPO

上一轮的四主体学习停留在零折扣、零迁移。对同一用户任务改变报价后，低、中敏感度用户仍选择固定动作，说明需要先学习合同费用比较，并在联合训练中持续覆盖多种报价。

## 修改的内容

1. **用户的选项共享评分网络。** 三个用户各自维护独立 PPO；同一个用户内部用同一网络处理十个选项，使某选项报价变化能够直接影响其得分。账单、自身延迟迁移损失及二者的和作为可观测经济特征输入。评分参数由 PPO 更新，没有最低费用选项标签、固定负成本权重或 argmin 动作规则。
2. **多样报价预训练。** 按日抽取结构化报价、独立随机分区分时折扣与统一折扣。用户使用原来的自身效用奖励，先以 gamma=0 学习当前合同比较。验证数据使用独立场景，精确可行费用最低选项只用于计算误差。
3. **平台动作压缩。** 平台选择一个 Discrete(55) 动作：原合同方案，以及时间、地区、时间与地区三类折扣形状，六档幅度与三档额度的组合。形状根据公开的参考节点电价与数据中心能耗形成；不使用私有敏感度、真实用户反应或事后利润筛选。55种结构化方案收缩了原来的任意12报价加3额度的空间。
4. **四主体联合训练。** 保留预训练用户参数与优化器，接入一个平台 PPO，轮流更新。用户继续比较当前合同，以gamma=0优化自身当前任务收益。对手参数冻结，90%按当前确定选择、10%从对手策略采样动作。用户更新阶段持续以0.4递减到0.2的概率遇到多样报价，维持报价覆盖；平台更新阶段由平台自己选择动作。
5. **严格按学习策略评估。** 验证与最终评估关闭随机报价注入，四个学习主体都使用确定性动作。精确响应用户、有限菜单和集中调度分别作为对照。

用户动作屏蔽使用公开的选项存在性、计算容量、带宽与额度预检查；供电和碳可行性继续由预约LP判断。所有任务仍保留原始合同，账单锁定、效用奖励、平台利润与社会成本口径不变。

## 训练与检查

预训练在场景0–63上进行；独立验证使用9000起的场景。逐个用户检查当前任务费用差和个人理性，再进入联合训练。最终10000起的测试场景仅用于完成训练后的比较。

```bash
python scripts/train_coordination_staged.py --seed 0 --pretrain-steps 16384 --pretrain-max-steps 65536 --joint-user-gamma 0 --opponent-sampling-probability 0.1 --cycles 32 --platform-days 512 --user-steps 1024 --eval-every-cycles 4 --eval-days 32 --validation-days 16 --output results/staged

python scripts/run_coordination.py --days 32 --checkpoints results/staged/checkpoints --catalogue-benchmark --output results/staged-comparison
```

训练日志分别记录用户预训练与联合训练的实际步数、优化器更新次数和固定验证集结果。`test_user_responses`另外用多样报价测量最终用户能否保持条件响应，而不只看主平台当前发布的一种报价。

`--pretrained-users <directory>`可从三个user_*.zip复用预训练权重与优化器；仍先验证合同选择质量，再初始化平台并进行联合训练。日志将预训练步数与本次联合步数分开记录。当前任务比较的模型采用即时收益；用户跨任务组合调度需要另建相应的长期状态与机会成本模型。

## 比较的含义

新旧主实验都使用四个学习主体。使用精确用户的对照用于判断剩余问题来自报价还是用户响应。55项菜单基准利用完整信息挑选可参与方案，具有信息优势；集中物理优化同时分配全部任务，没有支付约束。最终以同量完成、按期、用户收益、平台利润和系统资源成本共同判断协同效果。
