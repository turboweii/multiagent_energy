# 碳约束与输电拥塞下的分时分区算力定价与多智能体协调

当前实现采用 GPU 小时尺度、已接受旧合同上的两阶段改签，以及先补偿再分净收益的结算，见[当前机制说明](net_surplus_amendments.md)。本文保留最初框架，其中 CU 尺度、报价幅度、动作编码和基准属于早期版本。

## 1. 确定要研究什么

**研究目的：在同一批计算任务、相同计算工作量、相同任务截止期下，研究平台如何利用分时、分区算力服务价格，引导具有不同时间敏感度的独立用户自愿迁移或延迟任务，在满足输电网、计算容量和碳约束的同时降低社会总成本，并让用户与平台均有参与意愿。**

研究对象是电价、碳稀缺价和算力服务价格之间的传导与反馈。算价引起任务位置和时间变化，任务变化改变节点用电，电网重新出清又改变平台电费以及后续报价的收益。不能预先随机生成三条价格曲线，再以拟合这些曲线作为研究结果。

需要回答三个可验证的问题：

1. 在拥塞与碳约束下，任务时空灵活性实际能节约多少资源成本？
2. 其中多少节约能通过用户自愿接受、平台愿意提供的价格菜单实现？
3. 私有偏好、顺序预约与各主体独立学习，分别造成多大的效果损失？

多智能体用于表示利益不同、信息不同的主体，并学习其交互策略。它本身不是创新性结论。潜在研究贡献在于将电网与碳约束的边际信号转化为有参与激励的算价机制，并量化可实现的节约与集中调度潜力之间的差距。

与参考工作的关系：[Levy 等的 EnergyNet](https://ojs.aaai.org/index.php/AAAI/article/view/41229)提供多主体能量管理与交替训练的代码起点；[Xie 等的工作](https://ieeexplore.ieee.org/document/11668907)研究电力供给者、算力提供者与用户的多阶段决策。这里拟重点识别的是网络拥塞、碳上限、同量任务与自愿参与共同作用下的定价可实施性。是否形成足够的新贡献，要由这些明确因素的对照结果支持。

## 2. 第一版参与者与时间尺度

- 一个算力平台，管理三个电网节点上的三个数据中心。
- 三个独立企业用户，每个用户有低、中、高三类中的一种时间敏感度，每天各有四个任务。三个用户都有自己的 PPO。
- 电网运营者执行确定性的 DCOPF。它按规则出清，不训练一个可任意修改电价的 RL 主体。
- 碳政策给定全天排放上限，出清得到统一的碳稀缺价。第一版没有另设独立的策略性配额交易市场。

一天包含 48 个半小时时段；平台发布三个地区、四个六小时价格块的报价及三个地区的预约额度。随后用户按任务提交顺序选择合同，最后进行全天日前出清与结算。日内发布的任务合同不会因最终电价变化而重新改价。

这里采用确定性日前计划，所有方案共享当天的负荷、可再生出力、任务和碳上限。暂时不引入日前—实时预测偏差与二次结算。

## 3. 三种价格分别怎样形成

| 价格 | 第一版形成方式 | 单位与解释 |
|---|---|---|
| 节点电价 λ[n,t] | 带线路、发电容量和排放约束的 DCOPF，取节点电力平衡约束的对偶值 | 元/MWh；随地区、时间、边际机组和拥塞情况变化 |
| 碳稀缺价 μ | 同一出清中，全天碳排放上限约束的影子价格 | 元/吨；代表放宽一吨排放约束可节约的最小发电成本，可能为零 |
| 算力服务价格 p[n,b] | 平台发布有界价格菜单，用户选择后锁定账单 | 元/CU；p = 0.8 × (1 − discount)，折扣为 0–30%，间隔 5% |

电网求解：

\[
\min_{g,f,\theta}\;\sum_{t,k} c_k g_{kt}\Delta t
\]

约束包括节点功率平衡、DC 潮流关系、线路容量、机组出力上限，以及

\[
\sum_{t,k} e_k g_{kt}\Delta t\le B.
\]

计算任务对应的节点用电：

\[
P^{DC}_{nt}=P^{idle}_n+
\frac{\epsilon_n x_{nt}+E^{transfer}_{nt}}{\Delta t}.
\]

x 是该半小时完成的 CU 数，不是功率；ε 单位为 MWh/CU。输电网约束通过 DCOPF 的节点供需和线路容量影响可执行的任务位置及 λ。碳上限通过发电结构和 μ 影响 λ。电价已包含碳约束的机会成本，因此不会再给平台电费重复增加 μ×用电排放费。

实现采用 SciPy/HiGHS 稀疏 LP 作为反复训练的出清内核，并提供同模型的 PyPSA 转换与参考求解。测试比较了两者的成本、排放与对偶价格。线路采用有效电抗 rad/MW；PyPSA 参考网络使用 110 kV，并将有效电抗转换为欧姆。

μ 是碳总量约束的边际价值，不应解释成完整 ETS 的成交价。若研究重点变为配额供需和交易策略，需要扩展独立碳市场；当前研究重点是碳约束怎样通过电力与算力定价影响任务选择。

## 4. 用户意愿的量化与动作

任务 j 有固定工作量 W、原始地点、释放时间和硬截止期。选择延期 τ 小时、迁移到其他地区时，用户损失为：

\[
D_j=W_j\beta_i\tau_j+W_j\kappa_i I(迁移).
\]

用户比较“服务账单 + 延迟与迁移损失”，而不是服从平台的调度命令。

| 用户 | β，元/(CU·小时) | κ，元/CU |
|---|---:|---:|
| 低时间敏感度 | 0.006 | 0.004 |
| 中时间敏感度 | 0.025 | 0.008 |
| 高时间敏感度 | 0.090 | 0.015 |

每个仿真日 β 再乘以固定种子生成的 0.8–1.2 倍扰动。这些数值是实验参数，代表不同的意愿强度，不是调查得到的真实估计。后续通过成倍改变 β、迁移损失和可延迟窗口，检查结论在哪些偏好范围内成立。

例如中敏感度用户的一项 1,800 CU 任务，延期两小时损失 90 元，再迁移损失 14.4 元；服务费至少降低 104.4 元，用户才有接受这一方案的经济动机。

每个任务压缩为十个离散合同：

- 0：原地点、原时间、原账单的保底合同。
- 1：原地点、原时间，按新发布的算价收费。这样同地原时执行也能享受新价，避免人为要求“必须迁移才有折扣”。
- 2–3：原地点延期 1 或 2 小时。
- 4–9：另两个地区分别延期 1、2 或 3 小时。

所有选项保留完整 W 并在截止期内完成。远端执行包含数据传输容量、能耗与费用。预约替换原始保留时段，其他尚未决策任务的原始合同继续保留。计算容量、带宽、公开额度或供电碳约束不可行时，保留该任务原合同。

预约额度取容量的 50%、75% 或 100%，但不能撤回原始保留合同。所有方案都做物理准入检查；只有额外额度的决策是否启用不同。

## 5. 各智能体的状态、动作和奖励

| 主体 | 观测 | 动作 | 优化目标与代码奖励 |
|---|---|---|---|
| 平台 PPO | 背景负荷、可再生出力、原始合同的参考出清电价和碳价、原任务占用、各用户工作量、碳上限；不直接看到私有 β、κ | 12 个分区分时折扣 + 3 个地区预约额度，共 15 个 MultiDiscrete 分量 | 最大化服务收入减全部 DC 电费与运行迁移成本；奖励为相对原合同利润变化的归一化值 |
| 低敏感度用户 PPO | 自己当前任务的 W、释放/截止时间、β、κ，十个选项的账单/损失/容量信息，公开报价额度与剩余任务数 | Discrete(10)，选择一个合同 | 最大化自己的效用；奖励 = 10×(原账单−新账单−自身损失)/原账单 |
| 中敏感度用户 PPO | 同上，各自私有偏好 | 同上 | 同上，仅计自己的任务 |
| 高敏感度用户 PPO | 同上，各自私有偏好 | 同上 | 同上，仅计自己的任务 |

平台观测 485 维，单个用户观测 92 维。平台一天动作一次；每个用户每天四次动作。平台不是替三个用户一起做决策的单智能体。

采用四个独立 PPO，轮流更新一个，其他三个冻结；每次轮换重置旧环境状态。网络均为两层 64 单元 MLP，学习率 3e-4，4 个优化 epoch，熵系数 0.01。日志分别记录每个主体的实际交互步数与 optimizer 更新次数。

用户保留原合同，但学习过程中可能选择更差的方案，因此逐任务记录个人理性 IR。PPO 奖励没有强行把所有用户改成同一个社会成本目标，也没有在结算后撤销已接受合同以保护平台利润。

## 6. 研究目标与主体目标如何区分

机制设计希望降低：

\[
C=发电资源成本+计算及迁移运行成本+用户延迟及迁移损失.
\]

同时希望每个任务的新账单加损失不超过原账单，且平台利润不低于原合同利润。电费、算力账单属于参与者之间的支付，不在社会成本里重复相加。

主体独立学习利润和自身效用，并不自动等于社会目标最小化。实验要检验这两者是否一致：若平台更赚钱但系统成本上升，或者用户省钱依赖平台亏损，都不能算已经实现了目标机制。

第一版把价格菜单与预约规则作为给定机制，用 PPO 学习交互策略。集中优化和带参与条件的有限菜单搜索用于定位潜力及差距，不能用这些对照的结果替代四个学习主体的表现。

## 7. 仿真数据怎样准备

保留原 EnergyNet 的 48 时段结构与合成数据来源，新增本研究所需的电网与任务输入。

| 数据 | 来源或生成方式 |
|---|---|
| 背景负荷形状 | 原仓库 synthetic_household_consumption_test.csv，按天归一化后缩放为三地区 MW 负荷；原文件 13 个空值在读取时线性插值，CSV 不改 |
| 发电与输电网 | 三节点、三线路、煤电/燃气/可再生机组的合成参数 |
| 可再生出力 | 日照形状、风电正弦与随机云量的固定种子组合 |
| 任务 | 每个用户四项，工作量约 1,200–2,100 CU，执行一小时，位置/释放时间/截止期与原合同一同生成 |
| 用户偏好 | 上表三档 β、κ 与种子扰动 |
| 碳总量 | 在原始合同的经济调度排放与最低排放调度之间插值，紧度默认 0.35，保证原合同可执行；同一天各方案使用同一上限 |
| 电价与碳价 | 出清结果 |
| 算价 | 平台动作或预先公开的对照规则 |

CU 是抽象计算工作量单位，当前没有把它解释为某型号 GPU 的实际小时数。功率、能耗、价格与损失在各方案间保持统一口径。

## 8. 对照与后续实验

代码包含以下几组，运行结果分开标明其角色：

1. 统一算价与原始合同。
2. 固定公开规则：分时价、分时分区价、分时分区价加额度，折扣幅度预先固定为 20%；用户逐任务精确比较自己的费用。它们可能降低平台利润。
3. 四主体独立 PPO，作为主要学习方案。
4. 诊断对照：PPO 平台搭配逐任务精确用户；公开规则搭配 PPO 用户，帮助分辨报价学习与用户选择学习的问题。
5. 有限候选菜单基准：在披露的折扣形状与幅度集合里，选满足用户 IR、平台利润底线的最低社会成本方案。分时、分时分区、加额度的候选集合逐级包含。它使用完整偏好与方案结果挑选，是有信息优势的基准。
6. 物理 MILP：同时分配所有任务并优化发电，得到这些离散执行选项下的最低社会成本；不施加支付与参与条件。可选 LP 松弛作为更低的数学界。

集中优化与分散机制的差距同时包括完整信息、联合调度、顺序预约和参与条件的影响，后续要逐项做消融。不能将整个差距都归因于 PPO。

正式实验依次改变线路容量、碳上限紧度、用户 β 与任务灵活窗口。记录成对成本差、平台利润差、逐任务 IR、各用户收益、同量完成率、按期率、节点电价、碳价、排放、拥塞与弃电。碳上限持续绑定时，主要结果是同一碳约束下的成本变化，不应将其描述为额外减排。

## 9. 与原仓库的对应及运行

基于 CLAIR-LAB-TECHNION/energy-net，初始提交 a55083828ad4a484e44575b579a448cde3a4466a。在同一仓库新增 energy_net/coordination 与 scripts 下的训练/比较入口，沿用 Gym、SB3 PPO 与轮流训练的结构，并读取原始合成负荷。原来的电池 PCS 状态动作不适合任务合同，所以新建任务市场环境；原 ISO 直接定价部分替换为网络与碳约束出清模块。

模块分工：scenario.py 生成数据；grid.py 电网出清；market.py 价格、合同与结算；learning.py 四主体训练；baselines.py 调度及菜单对照。

从仓库根目录运行：

```bash
pip install -e '.[coordination,test]'
python scripts/train_coordination.py --seed 0 --cycles 8 --platform-days 32 --user-steps 128 --eval-days 8 --output results/ppo-seed0
python scripts/run_coordination.py --days 8 --checkpoints results/ppo-seed0/checkpoints --output results/comparison
python -m pytest tests/coordination tests/unittests -q
```

第一轮为单个训练种子 0 的功能联调：平台实际 256 步、32 次 optimizer 更新；每个用户实际 1,024 步、128 次 optimizer 更新。训练场景 0–63，评估场景 10000–10007。它验证四主体确实分别训练与结算；完整性能实验需要更长训练并检查学习曲线与对照差距。
